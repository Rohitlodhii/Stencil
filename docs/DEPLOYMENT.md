# Render deployment

## Repository layout

- `apps/desktop`: the full React/Vite web interface and Tauri desktop shell.
- `apps/api`: examination, evaluation, upload, demo, and scanner-support API.
- `apps/auth-service`: coordinator and examiner authentication service.
- `apps/gateway`: the public reverse proxy; its production image also serves the Vite build.
- `apps/web`: a legacy/minimal Next.js scanner interface. It is buildable but is not the primary Stencil UI.
- `pyproject.toml` and `uv.lock`: the shared Python workspace manifest and lockfile.
- `pnpm-workspace.yaml` and `pnpm-lock.yaml`: the shared JavaScript workspace manifest and lockfile.
- `render.yaml`: the Render Blueprint for the web gateway, API, auth service, and Postgres database.

## Blockers fixed

The previous API Dockerfile assumed `apps/api` was both the Docker build context and a complete uv project. It attempted `COPY uv.lock ./`, but the only lockfile correctly lives at the repository root. It also omitted the root `pyproject.toml`, copied `app` and `src` from the wrong paths when using a root context, used a fixed port, and called `uvicorn` outside a guaranteed environment.

The Dockerfiles now use the repository root as their context, copy the complete uv workspace metadata before a frozen sync, install only the target package, run as non-root users, and bind to `${PORT}`. The lockfile is validated and committed. The gateway image builds the primary Vite UI and serves it on the same public origin used for API and authentication requests.

The old Next.js Dockerfile also omitted `pnpm-lock.yaml` and its workspace package manifest before a frozen install, then copied non-existent standalone paths. It now uses the root pnpm context and the monorepo standalone output layout.

## Render services

Create or update the Blueprint from the repository-root `render.yaml`. Render must use these exact Docker settings:

| Service | Dockerfile | Build context | Health check |
| --- | --- | --- | --- |
| `stencil-web` | `apps/gateway/Dockerfile` | repository root | `/health` |
| `stencil-api` | `apps/api/Dockerfile` | repository root | `/health` |
| `stencil-auth` | `apps/auth-service/Dockerfile` | repository root | `/health` |

The Blueprint creates `stencil-db` and injects its private connection string into the API and auth service. Both services currently run idempotent `CREATE TABLE IF NOT EXISTS` startup migrations; the repository does not use Alembic. Schema changes beyond the MVP should introduce versioned migrations before production data is stored.

## Manual configuration

The Blueprint deliberately contains no credentials. Add these in the Render dashboard only when the corresponding integration is required:

- AI: `LUNA_API_KEY`, and optionally `LUNA_BASE_URL` and `LUNA_MODEL`.
- S3: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, and `S3_BUCKET`.
- Optional CORS restriction for direct API access: `CORS_ORIGINS` as a comma-separated list.
- Production mode: set `STENCIL_DEMO_MODE=false` after AI/storage and production data paths are configured.

`AUTH_JWT_SECRET` is generated by the Blueprint and must not be copied into the repository. The physical camera scanner is intentionally not deployed to Render because it requires hardware on an examiner workstation; the hosted scanner page reports that service as unavailable rather than activating a browser camera silently.

## Local validation commands

```powershell
python -m uv lock --check
python -m uv run --package api --with pytest python -m pytest -q apps/api/tests
corepack pnpm --filter desktop typecheck
corepack pnpm --filter desktop build
docker build -f apps/api/Dockerfile -t stencil-api .
docker build -f apps/auth-service/Dockerfile -t stencil-auth .
docker build -f apps/gateway/Dockerfile -t stencil-web .
docker run --rm -e PORT=10000 -e STENCIL_DEMO_MODE=true -p 10000:10000 stencil-api
```

After starting the final command, `http://localhost:10000/health` must return HTTP 200. A degraded database/storage/AI status is expected when those external services are not configured; it is not replaced with an unlabelled mock.
